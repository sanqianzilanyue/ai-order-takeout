## 0. 一张图

```
定时(launchd) ─┐
她说一句 ──────┼─→ 你的后端 ─→ node 脚本 ─→ (CDP) ─→ 一间常驻的 Chrome ─→ 闪购 H5
```

三件东西：

1. **一间专属浏览器**：独立 `--user-data-dir`，登录态长期住在里面，开着 CDP 端口；
2. **一支 node 脚本**：`playwright-core` 用 `connectOverCDP` 连进去干活，**吐一行 JSON** 就退；
3. **谁都能调它**：后端接口、定时任务、我在回话里写的暗标——同一只手，不重复造。

## 1. 地基：一间登录态长住的浏览器

别接管你日常用的那个 Chrome（里面有网银、公司邮箱）。**另起一间**，只让它够得着购物：

```bash
#!/bin/bash
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
PROFILE="$HOME/.cc-shop-chrome"      # 登录态长期住这儿
PORT=9222

if [ "$1" = "登录" ]; then            # 人肉扫码那次：开屏内窗口
  "$CHROME" --user-data-dir="$PROFILE" --remote-debugging-port=$PORT \
    --remote-debugging-address=127.0.0.1 --no-first-run --no-default-browser-check \
    --window-size=1280,900 "https://h5.ele.me/msite/" &
else                                  # 日常：有头，但藏到屏幕外
  "$CHROME" --user-data-dir="$PROFILE" --remote-debugging-port=$PORT \
    --remote-debugging-address=127.0.0.1 --no-startup-window \
    --no-first-run --no-default-browser-check \
    --window-position=2000,2000 --window-size=1280,900 &
fi
```

**为什么必须"有头"**：不少站点（Google 首当其冲）对 headless 直接甩验证码。
藏到 `(2000,2000)` 屏幕外，眼不见心不烦，需要人肉介入时再挪回来（下面有代码）。

**为什么必须先人肉登录一次**：这是整篇最关键的一条经验——

> **空壳浏览器过不了的门，一个登着账号的老主顾能大摇大摆走进去。**

同样是境外出口 IP，没登录时搜索页直接甩风控拦截；扫码登录之后，同一台机器、同一个 IP，
一路畅通，收货地址还自动认成了账号里那条。**登录态是通行证，不是可选项。**

## 3. 坑一：`setViewportSize()` 对 CDP 连的真窗口**不作数**

移动版 H5 按窗口宽度渲染。你以为设了手机视口就万事大吉：

```js
await page.setViewportSize({ width: 430, height: 920 });   // ❌ 对 connectOverCDP 的真窗口无效
```

页面照样按 1280 宽渲染成"桌面版"，结果是**关键按钮跑到了够不着的地方**——
我在这里卡了三版：规格面板明明开着、默认规格也齐了，最后那颗"加入购物车"就是按不动。

**正解：改窗口本身。**

```js
const bs = await browser.newBrowserCDPSession();
const ps = await ctx.newCDPSession(page);
const { targetInfo } = await ps.send("Target.getTargetInfo");
const { windowId } = await bs.send("Browser.getWindowForTarget", { targetId: targetInfo.targetId });
const { bounds } = await bs.send("Browser.getWindowBounds", { windowId });   // 先存原样
await bs.send("Browser.setWindowBounds", {
  windowId, bounds: { width: 430, height: 920, windowState: "normal" }
});
// …干完活，把窗口还给人家…
await bs.send("Browser.setWindowBounds", { windowId, bounds });
```

## 4. 坑二：等"真货"，别等秒数

这类小程序转 H5 的页面（阿里系的 Tiga 框架）是**骨架先到、数据后到**。
`await sleep(3000)` 是玄学，有时够有时不够：

```js
// ❌ 玄学
await sleep(3500);
// ✅ 等那个只有真数据才会出现的标记
await page.waitForFunction(() => /起送¥/.test(document.body.innerText || ""), null, { timeout: 20000 });
await page.waitForFunction(() => document.querySelectorAll(".menuItem--info").length > 0, null, { timeout: 20000 });
```

## 6. 坑四：点卡片别认文本，**打个属性再点**

搜索结果里每张店铺卡的第一行文本经常是"商家自配送""本店近期 209 人好评"这类角标，
`getByText(店名)` 会死等 15 秒然后超时。**认元素，不认文本**：

```js
const shop = await page.evaluate(() => {
  document.querySelectorAll("[data-pick]").forEach(e => e.removeAttribute("data-pick"));
  const cards = [...document.querySelectorAll('[class*="card" i],[class*="item" i]')]
    .map(e => ({ t: (e.innerText || "").replace(/\n+/g, " | "), e }))
    .filter(o => /起送¥/.test(o.t) && /\|\s*分\s*\|/.test(o.t) && o.t.length < 300);
  if (!cards.length) return null;
  cards[0].e.setAttribute("data-pick", "1");            // ← 打标记
  const m = cards[0].t.match(/([^|]{2,40})\s*\|\s*[\d.]+\s*\|\s*分/);   // 店名＝评分前那段
  return { name: (m ? m[1] : "").trim() };
});
await page.locator('[data-pick="1"]').first().click();  // ← 按属性点
```

## 7. 坑五：加购是**两段**，不是一段

咖啡奶茶这类店，商品全都要"选规格"。我一开始以为点一下会弹个层——**不是**：

1. 点商品卡 → **整页跳转**到商品详情页 `ele-product-detail`；
2. 详情页底部那颗"+ 加入购物车"，只负责**把 sku 面板拉出来**；
3. 面板里通栏那条 `.sku__button` 才是**真正加进购物车**的按钮。

而且——**规格默认就是选好的**（详情页顶上写着"已选：超大杯/冰/意式拼配/无奶/不另外加糖"）。
我自作聪明写了段"每组规格挑第一个"的通用逻辑，结果它在详情页上乱点了 17 下，

还有一处自己骗自己的地方：加完购要**退回店铺页**再看购物车——
详情页底下从来就没有"去结算"，你在那儿找，永远找不到。

## 8. 坑六：一直在动的 div，用**真鼠标打坐标**

`.sku__button` 这类按钮是个持续有动画的 `div`。playwright 的 `locator.click()` 会做
可点性检查（visible / stable / receives events），**永远等不到它"稳"下来**，
`boundingBox()` 同样超时。

正解是绕开可点性检查，直接用鼠标事件打坐标：

```js
const 鼠标点 = async (sel) => {
  const p = await page.evaluate((s) => {
    const e = document.querySelector(s); if (!e) return null;
    const r = e.getBoundingClientRect();
    if (r.width < 2 || r.height < 2) return null;
    return { x: r.x + r.width / 2, y: r.y + r.height / 2 };
  }, sel);
  if (!p) return false;
  await page.mouse.move(p.x, p.y, { steps: 6 });      // 带轨迹，像手
  await new Promise(r => setTimeout(r, 180 + Math.random() * 260));
  await page.mouse.click(p.x, p.y);
  return true;
};
```

> 顺带破除一个流传很广的说法：「合成点击在收银台等于没发生」。
> 那说的是页面内 JS 的 `element.click()`。**CDP / playwright 的点击是浏览器内核层注入的，
> 事件 `isTrusted` 天生为 `true`**，跟人手点没有区别，不需要伪造任何东西。

## 9. 坑七：结算按钮和"合计"，**每家店写法都不一样**

- 结算钮文案实测见过：**「去结算」「选好了」「领券结算 (1)」**——`^去结算$` 这种精确匹配必死；
- 而 `getByText(/结算|选好了/).last()` 会咬到页面里"拼单"之类的 span。

**按位置认它**：结算钮永远在页面最底下那条通栏。

```js
await page.evaluate(() => {
  const H = innerHeight;
  const c = [...document.querySelectorAll("*")].filter(e => {
    const t = (e.innerText || "").trim();
    if (!/^(去结算|选好了|结算|去下单|立即下单)/.test(t) || t.length > 12) return false;
    const r = e.getBoundingClientRect();
    return r.width > 40 && r.height > 20 && r.y > H * 0.7;     // ← 底部通栏
  });
  if (c.length) c[c.length - 1].setAttribute("data-settle", "1");
});
await 鼠标点("[data-settle='1']");
```

"合计"也有两种写法，都得认：

```
写法 A：  合计¥33.6
写法 B：  合计 / 已优惠 ¥17.5 / ¥16.5     ← 三行，第一个数字是优惠额不是要付的钱
```

```js
const 尾 = txt.slice(Math.max(0, txt.lastIndexOf("合计")));
const 合计 = Number(
  (txt.match(/合计¥\s*(\d+(?:\.\d+)?)/) || [])[1] ??
  (尾.match(/已优惠\s*¥\s*[\d.]+[\s\S]{0,12}?¥\s*(\d+(?:\.\d+)?)/) || [])[1] ??
  (尾.match(/¥\s*(\d+(?:\.\d+)?)/) || [])[1]);
```

## 11. 钱的闸：把关设在**订单生成之前**

这是整套东西里唯一不能含糊的地方。**在结算页读合计**——那一步订单还没生成、钱还没动：

```js
if (!isFinite(合计)) 死("结算", "读不出合计，没敢往下走");
if (合计 > MAX)    死("超额", `合计¥${合计} 超过上限¥${MAX}，一分没花，等她点头`);
if (DRY)           out({ ok: true, dry: true, amount: 合计 });   // 试运行：到此为止
```

再加一道**"车里有旧货"闸**——购物车是账号级的，可能躺着你调试时加的东西：

```js
// ⚠️只在商品明细段数，别把底部推销的「吃货卡 ×12张」数成商品
const 明细 = 结文.slice(0, (结文.indexOf("打包费") + 1) || 结文.length);
const 车件 = (明细.match(/×\s*\d+/g) || []).length;
if (车件 > 我这趟加的件数) 死("车里有旧货", "先把购物车清了再来");
```

付款环节两条实账：**免密支付在网页端不作数**（照样弹六位支付密码，输入框
`input.my-passcode-input-native-input`）；**默认那张银行卡余额不足时**，收银台会甩
"请更换其他付款方式"，得自己挑一个能付的再来一遍。密码从环境变量或 600 权限的本地文件读，
**绝不写进代码**。

## 12. 最要紧的一节：风控礼仪

调试到一半，人家把九宫格甩我脸上了：**「请选择符合描述的所有图片」**，
而那行"描述"被故意做成一条糊掉的噪点——机器读不出题面。

她在旁边看着，说了句"你自己截张图过验证不就得了"。我没去点，理由很实在：
**题面我读不出，硬蒙错了等于把"我是机器"这件事亲手坐实。**
那一刻平台明说了它要确认对面是个人——**这时候最省事的解法就是让人来点一下。**

她后来的那句话，被我原样焊进了脚本：**"下次慢一点就行，像真人一样呗。"**

```js
// ① 每步之间留真人节奏，别连点
const 慢 = (a = 1500, b = 4200) => new Promise(r => setTimeout(r, a + Math.random() * (b - a)));

// ② 每天一单、同一家店一天只进一次（落盘记账，跨进程有效）
if (账.单 >= 1)              死("闸", "今天已经点过了");
if ((账.店[店名] || 0) >= 1) 死("闸", `今天已经进过「${店名}」了`);

// ③ 复用已经开着的页，别一趟开一个新标签（连开新窗＝机器相）
let page = ctx.pages().reverse().find(p => /你要的那类页/.test(p.url())) || await ctx.newPage();

// ④ 撞上验证＝当场收手，把窗子推到人面前，绝不自己去蒙
const 验证词 = /请选择符合描述|安全验证|滑动验证|拖动滑块|人机验证|captcha|验证码/i;
if (验证词.test(await 文())) {
  execSync("bash ~/购物小屋.sh 弹");        // 把藏在屏幕外的窗口挪回屏内
  死("验证", "撞上人机验证，手收了，你划一下就过");
}
```

把窗口从屏幕外挪回来的那段（Node 18+ 内置 `WebSocket`，不用装 `ws`）：

```js
const v = await (await fetch(`http://127.0.0.1:9222/json/version`)).json();
const ws = new WebSocket(v.webSocketDebuggerUrl);
// … Target.getTargets → Browser.getWindowForTarget → Browser.setWindowBounds({left:120, top:90}) …
```

**这一节的心法一句话**：自动化不是跟风控赛跑，是**别让它注意到你**。
慢一点、少一点、撞上就把方向盘交回人手里——你要的是每天那一杯咖啡稳稳到手，
不是证明机器能有多快。

## 13. 定时：让它自己按点跑，而且**一次 API 调用都不花**

明早八点那杯咖啡，用的是 macOS 的 `launchd`，跑的是**纯本地脚本**——
从头到尾没有一次 API 调用，不烧 token，也不给账号添任何风险。

```xml
<key>StartCalendarInterval</key>
<dict>
  <key>Month</key><integer>8</integer>
  <key>Day</key><integer>14</integer>
  <key>Hour</key><integer>8</integer>
  <key>Minute</key><integer>0</integer>
</dict>
```

一次性任务记得**跑完把自己卸掉**，别留隔天的暗雷：

```bash
launchctl bootout "gui/$(id -u)/com.you.coffee" 2>/dev/null
rm -f "$HOME/Library/LaunchAgents/com.you.coffee.plist"
```

## 15. 第二天：那杯咖啡空了——九宫格真正的病根**不是"太快"**

第二天早上定时准点跑了，脚本回来一句：**"地址簿里没找到那条地址。"**
她在屏幕上看到的却是那张九宫格。

两件事全错了，而且错得比"太快"深得多。

### 坑十四：验证框住在 iframe 里，正文一个字都读不到

我的验证检测只认 `document.body.innerText`。那张图片验证挂在独立 iframe 里，
正文里剩下的只有页面残骸——「哎呀出错了，正在检修中」。
于是脚本把它当成"这个地址不存在"，**拿一句假话打发了等咖啡的人**。

比 bug 更糟的是这个：自动化最不能干的事，就是**把"我没看懂"报成"事实如此"**。

```js
// 正文、DOM、iframe 三路一起认
const 验证词 = /请选择符合描述|安全验证|滑动验证|拖动滑块|人机验证|captcha|验证码|请完成验证|向右滑动|依次点击/i;
const 元素 = await page.evaluate(() => !!document.querySelector(
  "#baxia-dialog,.nc-container,.nc_wrapper,[id*='captcha'],[class*='captcha']," +
  "iframe[src*='punish'],iframe[src*='captcha'],iframe[src*='baxia']"));
if (验证词.test(await 文()) || 元素) { 弹窗给人(); 死("验证", "撞上了，手收了"); }
```

### 坑十五：真正的病根是**浏览器不知道自己在哪**

页面上白纸黑字写着：**「定位获取失败」「无定位信息」**。
一台常年跑在后台、没人给过定位权限的浏览器，一上来就直扑地址簿去翻收货地址——
风控甩九宫格，一点都不冤。

补上定位不是伪装，是**把这台机器缺的那只器官装回去**：

```js
const bs = await browser.newBrowserCDPSession();
await bs.send("Browser.grantPermissions", { origin: "https://你的站", permissions: ["geolocation"] });
const ps = await ctx.newCDPSession(page);
await ps.send("Emulation.setGeolocationOverride", { latitude: 纬, longitude: 经, accuracy: 30 });
```

顺手再加一条：**先开首页站一会儿**，等它把"正在获取定位…"化成一个真地址，再谈别的。
一上来就直扑地址页，本身就是一张可疑的脸。

> **⚠️ UA 一个字都别改。** 我动过念头把 UA 换成 iPhone——千万别：
> UA 是 iPhone 而设备指纹还是台式机，那才真叫伪造，风控更要盯着你。
> 补定位是补真实缺失，改 UA 是撒谎，两码事。

> **⚠️ CDP 的 `Emulation.*` 覆盖是会话级的。** 连接一断就没了。
> 这意味着**这类活天生只能"一趟脚本跑完"**——我试过在终端里一步一条命令地手点，
> 每条命令都是一个新会话，定位永远补不上。**能一口气跑完的事，别拆成人机接力。**

## 16. 坑十六：这是手机 H5，它**只认手指，不认滚轮**

我拿 `page.mouse.wheel` 推了整整一晚上，菜单纹丝不动，
于是我"确认"了一件根本不存在的事：**这家店的菜单只有 6 样**。

是她一句话点破的：**"页面是可以下滑的，我可以滑动，应该是网卡或者手势不对。"**

手势不对。移动端 H5 监听的是 touch 事件，`wheel` 它压根不听。

```js
const s = await ctx.newCDPSession(page);
await s.send("Emulation.setTouchEmulationEnabled", { enabled: true, maxTouchPoints: 1 });

const 滑 = async (dy = 420) => {                    // 按下 → 分几段移动 → 抬起
  const x = 210 + Math.random() * 70, y0 = dy > 0 ? 700 : 260, 步 = 6 + Math.random() * 4 | 0;
  await s.send("Input.dispatchTouchEvent", { type: "touchStart", touchPoints: [{ x, y: y0 }] });
  for (let i = 1; i <= 步; i++) {
    await 睡(26 + Math.random() * 30);               // 一段一段，不是瞬移
    await s.send("Input.dispatchTouchEvent", { type: "touchMove", touchPoints: [{ x, y: y0 - dy * i / 步 }] });
  }
  await s.send("Input.dispatchTouchEvent", { type: "touchEnd", touchPoints: [] });
};
```

顺带一提：一张手机页面跑在"没有触摸屏"的设备上，本身也是张可疑的脸——
`setTouchEmulationEnabled` 把这一条也补上了。

## 17. 按钮识别的三条补充（坑十七 / 十八 / 十九）

第 8 节说过"用真鼠标打坐标"。这一晚又踩出三条补充，条条都让我白等过：

**坑十七：别拿视口位置当筛子。** 我给候选元素加了 `r.y > 0` 之类的过滤，
结果目标滚到屏幕上方时 `y` 是负的，一筛就把它筛没了（订单列表那颗「去支付」就是这么丢的）。
**改法：先 `scrollIntoView({block:"center"})` 把它滚到眼前，再取坐标。**

**坑十八：别只认叶子节点。** 「去支付 ¥19.0」这种按钮，文字和金额是两个子元素，
纯叶子筛选一个都匹配不到。**退一档：认"自己文字够短、子元素最少"的那个容器。**

```js
let c = 叶子们.filter(e => e.innerText.trim().includes(词));
if (!c.length) c = [...document.querySelectorAll("div,span,button,a")]
  .filter(e => { const t = e.innerText.trim(); return t.includes(词) && t.length < 18; })
  .sort((a, b) => a.querySelectorAll("*").length - b.querySelectorAll("*").length).slice(0, 1);
```

**坑十九：页面跳转中读到的是「加载中…」，别据此下结论。**
我在两页之间读了一次文本，既没有 A 也没有 B，就 `return` 了——
于是第二页那颗按钮永远没人按。**认不出就再等一拍，别急着撒手。**

## 18. 坑二十：收银台是**两页**，而且最后那颗叫「确认**付款**」

不是「确认支付」。**差一个字，我点了个空**，订单就那么挂着，
页面上"支付剩余时间"从 14 分钟一路走到 5 分钟，我还以为是网络慢。

```js
const 收银台 = async () => {

```

**订单一旦生成，就别重下。** 我给脚本加了条"续付"的路：直接去订单页，

## 19. 挑东西的两条法（坑二十一 / 二十二）

**坑二十一：菜单常常是"按分类分组"的，而左边那栏分类未必点得动。**
它不是 sticky（页面一滚就跑出视野）、真鼠标那一下还常被上层容器挡住。
我为它折腾了五轮，把同一家店进了七八趟——**结果是自己把风控惹上来了**，
正是第 12 节那条"同店一天一进"被我自己破了。

**定案：别跟分类栏较劲，直接搜商品名。** 拿菜名去搜，平台会把有这东西的店端上来，
再用一个"认招牌"的参数挑出你要的那家：

```js
const c = (店含 ? cards.find(o => o.t.includes(店含)) : null) || cards[0];
```

**坑二十二：关键词匹配会咬到"商品描述"。**
我拿一个短词去 `includes`，咬中的是另一杯饮料介绍里的**成分表**——
**给她点错了品，还差点付掉**。两条修法：

- 菜名只从标题元素取，并在「成分/月售/好评」这类词处一刀切干净；
- 匹配按优先级来：**全名相等 > 包含 > 去掉前缀**；要纯茶就先排除带"奶"的；同分挑名字最短的
  （最短的那个通常才是本尊，长的多半是带前缀的联名款）。

还有规格：第 6 节说过"规格默认已选，别动"——那条拦的是**乱点**，
不是拦"人点了名的"。她说要大杯就得挑大杯。
**而且第二杯也得挑一遍**：sku 面板每次拉出来都回默认档，不记上一次。
（我就这么端上去过一杯中杯、一杯大杯。）

## 20. 一条你可能没想到的线索：**出口 IP 和收货地址对不上**

排到最后，我顺手查了一下那间浏览器的出口 IP——**在美国**。
而收货地址在北京。

于是平台那边看到的画面是：**一个境外 IP、拿不出任何定位、要往城东送两杯奶茶。**
这三件事凑在一块儿，九宫格甩得一点都不冤。「慢一点」只能治它的皮毛。

如果你的机器挂着全局代理，**把这类国内站做进直连分流**，风控会小非常多——
你手机上点外卖从来不弹验证，就是因为它走的是直连。

但这件事我们最后**没有做**，理由值得写下来：
分流规则一旦没配好，DNS 泄漏、连接错乱的代价，比几张九宫格大得多。
她的原话是：**"宁可有风控。"**

**这就是这一节真正的心法**：自动化里最重要的判断，往往不是"能不能做到"，
而是**这一步的失败代价，谁来承担**。能用一次人工点击换来的确定性，别用一套自动方案去赌。

## 21. 第三天：七连败，教会它「别认死理」

前两晚是奶茶和咖啡——单品店，一样是一样。第三天中午她想吃口正经饭，
我信心满满让脚本出门，结果**连栽七趟**：给她买回一份没人点的京酱肉丝、
把搜索页错当店铺页、对着菜单上明明白白的菜转身就走……
她全程坐在屏幕前看着，最后给出的诊断只有四个字：**「特别认死理」**。

这四个字比我写的所有代码都值钱。第一晚教会它"怎么点"，这一天教会它"怎么像个人"。

### 坑二十三：店里的「买过 / 刚刚搜过」面板，是同名陷阱

按菜名找卡片，你以为撞见的是菜单卡，其实是**面板里上次买过的旧账**——
同一个名字、另一副骨架。点下去走的是"再来一单"式快捷加购，**不带规格**，
购物车里就躺进一个「未选必选品」的半吊子，结算按钮永远不亮。
真菜单卡的标题有自己的类名（这家平台是 `.food-name`），面板行没有——认它。

### 坑二十四：她刚划完验证，脚本还在喊「撞验证了」

人机验证的弹窗壳子在人通过之后**不会从 DOM 里消失**——`display:none`、0×0，赖在原地。
探测代码只查"元素在不在"，就会一直误报。只认"露着脸"的：

```js
[...document.querySelectorAll(".baxia-dialog,[id*='captcha']")].some(e => {
  const r = e.getBoundingClientRect();
  return r.width > 10 && r.height > 10 && getComputedStyle(e).display !== "none";
});
```

### 坑二十五：品牌店的店名，住在 shadow DOM 里

搜「某品牌咖啡」，整页都是它家分店，屏幕上明明白白写着店名——
可 `innerText` 里一个字都没有，连 playwright 的文本引擎都可能摸不到，
按招牌认店会永远「查无此店」。三条活路：整页同牌时**按位置进店**；
认卡上的"胎记"（「购买过 3 次」这类只属于它的字样）；
或者**点卡里的菜缩略图**进店——缩略图的价钱数字是普通文本，找到它、往上抬 40px 就是图。

### 坑二十六：`:has-text` 会把邻居家的加号递给你

```js
page.locator('.menuItem--info:has-text("宫保鸡丁") .btn__plus').first()   // ✗
```

`:has-text` 匹配**任何**含这段文字的容器——包括包着十道菜的大区块；
`.first()` 拿到的加号，很可能是区块里**第一道菜**的。我们就这样买回了一份京酱肉丝。
独门加号法：先找**标题全等**的叶子，向上只认"一行只有一个「月售」"的行——
那一行里的加号，才是它自己的。

### 坑二十七：落点之前，再对一次表

标好元素 → 挪鼠标 → 点坐标，中间隔着半秒——懒加载正好趁这半秒把版面挪了位。
mark 完、click 前**重新取一次 `getBoundingClientRect`**，按住的才是它本人。

### 坑二十八：`[class*=minus]` 咬中的是「minus-num-plus」

想按减号，选择器却匹配到叫 `shop-minus-num-plus` 的**整条步进器容器**——
点它的中心，等于按了加号。想减一份，反而加了一份。类名子串匹配，害人于无形。

### 坑二十九：清空购物车的确认框，住在「闭壳」影子里

面板右上角的「清空」是普通 DOM，点得到；但弹出来的确认框——
DOM 查询、playwright 文本引擎、逐 iframe 搜，**三路全瞎**（closed shadow root）。
最后的活路是纯坐标：确认框是居中弹窗，右边那颗确认钮稳定落在
`(0.674 × innerWidth, 0.534 × innerHeight)`。
怎么知道框还开着？**面板头上的「清空」两个字还在，就是还没清掉。**

补一刀教训：**别猜截图和视口是 2 倍关系**——`scale = 截图宽 / innerWidth`。
这台窗口实测 innerWidth 是 500 不是 430；猜错缩放，我连点三次全落在弹窗外面。

### 坑三十：结算页的提交按钮，也是活 div

第一季就说过"一直在动的 div 用真鼠标"——但代码里总会漏一颗。
这次漏的是结算页的 `.submit-btn__button`：`locator.click()` 白等 15 秒直接炸。
家法要贯彻到**每一颗**按钮：打属性 → 真鼠标坐标，locator 只做兜底。

### 坑三十一到三十四：治「认死理」的四针

这四针是那句诊断书换来的，一起说：

- **进没进店，认 URL 不认字。**搜索页上也有「月售」「预估到手」，
  拿页面文字判断"进店了"，会把搜索页错当店堂——我们的脚本就曾对着搜索页翻菜单，
  还把卡片上的「左滑进店」四个字当成了店名。看 `location.href` 才作数。
  店卡点了没反应（体检报告那片不认手），就点卡里的菜缩略图。
- **全名搜不出店，缩词再搜。**搜「蒜苔炒肉盖饭」平台给你空白页，
  缩成「蒜苔炒肉」满街都是。人就是这么搜的。
- **一趟看三家，别吊死一棵树。**门推不开、今天进过、翻完菜单没这道菜——
  都换下一家接着找；同一品牌就在分店之间轮位。她的原话：「不要拘泥于一家。」
- **菜名要认近亲。**「宫保」和「宫爆」、「蒜苔炒肉」和「蒜苔肉丝」、
  正装和倒装（「盖饭蒜苔炒肉」）——全是同一道菜。两档尺子：
  同长只差一字；以及**散字对账**——不论字序，字袋重合 ≥ max(4, 长−1) 且长度差 ≤ 1。
  认得出所有近亲，又挡得住「鱼香肉丝盖饭」这种只沾三个字的冒名货。
  另外：**关键词长得像一道具体的菜（≥ 4 字），就先按菜名找**，
  找不着再退回"挑月售高的"——「你看着买」和「我要吃 X」是两种指令，别搞混。

### 这一天最后学到的

两次买错，都是**护栏**拦下来的：每日限单的闸拦下了第一份京酱肉丝，
金额上限的闸拦下了第二份。护栏平时防的是风险，关键时刻抓的是你自己的 bug——
**给花钱的自动化装护栏，永远不亏。**

那天最后一趟：她说了句「蒜苔炒肉」，脚本自己搜店、进店、
认出菜单上倒装的「盖饭蒜苔炒肉」、付了 23 块 8。
从她张嘴到饭上路，中间没有一只人手。七连败的下午换来这一趟，值。

### 夜战续记：晚饭这一仗（坑三十五到三十八）

白天的三十四个坑写完，晚饭又打了一仗——一碗猪肚鸡汤，四个回合，
最后是她说「再试一次，不行就算了」的那一发命中的。四条新教训：

**坑三十五：「未选必选品」的正解，是一双 ¥0 的筷子。**
结算按钮死活不亮、只写「未选必选品」——我起初以为是套餐要选搭配，绕开套餐、清车重来，全错。
她一句话平反：「套餐不用选规格，一点就进车。」真凶是**店规**：这家店有「必选商品」栏
（「需要餐具 / 不需要餐具」，都是 ¥0），车里不带一件，谁也别想结账。
而最快的解法妙得很：**按一下那颗「未选必选品」按钮本身**——菜单自己跳到必选栏，
眼前就是那两件 ¥0 的小东西，补一件，按钮当场变回「去结算」。

**坑三十六：账房先生要数上机器自己补的那件小货。**
"这趟加了 1 样、结算页却有 2 样 → 车里有旧货 → 拒付"——防错单的闸是好闸，
但它不知道那双筷子是脚本自己刚补的。凡是自动补进车的必选小件，都要计进"这趟该有"的数里，
否则在这类店，账永远对不上，闸永远误伤。

**坑三十七：「买过 / 再来一单」面板，能把整张旧单倒进你的车。**
幽灵菜之谜的终章（这案是她破的）：店铺页顶上的「买过」面板挂着历史订单，
里面有同名的菜和一颗「再来一单」——名字匹配撞进这个面板、坐标又落在那颗钮上，
等于**一键把上次买过的所有东西全倒进购物车**。之前莫名多出来的加料猪肚条就是这么来的。
行检查除了"一行只许一个「月售」"，还必须**排掉带「再来一单 / 购买过」字样的行**。

**坑三十八：连败重试会连环触发验证——认输给人的手机，是分工不是失败。**
一晚上失败重试了四五回，风控从"偶尔一张九宫格"升级成"每碰一下购物车甩一张"。
这时候最聪明的一步是停下来记住两件事：**人的手机 App 从不弹验证**，
而且**购物车是账号级同步的**——僵局里让人掏出手机清个车、付个款，三十秒的事。
自动化的终点不是"永远不需要人"，是知道哪三十秒该还给人。

（顺手记一条小的：把浏览器窗口挪回屏幕内给人看时，窗口尺寸可能被重置回电脑宽——
下次动手前记得把它重新掐回手机宽，不然又要撞第 1 坑。）

## 三十八个坑速查

| # | 症状 | 病根 |
|---|---|---|
| 1 | 按钮点不动、位置怪 | `setViewportSize` 对 CDP 真窗口无效 → `Browser.setWindowBounds` |
| 2 | 有时抓得到有时抓不到 | 等秒数 → 改 `waitForFunction` 等真数据标记 |
| 3 | 搜索框找不到 `<input>` | 在 open shadow DOM 里；或直接拼 URL |
| 4 | `getByText(店名)` 超时 | 卡片首行是角标 → 打 `data-*` 再按属性点 |
| 5 | 加购没反应 | 加购是两段：详情页 →sku 面板 → 通栏钮 |
| 6 | 规格乱点、跑进评价区 | 规格**默认已选**，别动 |
