# 任务交接记录规范

`docs/handoff/` 用于保存轻量、可追溯的任务交接记录。以后每次任务出现以下任一情况时，
都应在本目录新增一份 handoff 记录：

- 任务完成
- 任务暂停
- 执行报错或被阻塞
- 需要用户接手操作

建议使用 `YYYY-MM-DD-简短任务名.md` 作为文件名；同一天同名任务可追加序号。记录应反映
写入当时的真实状态，不应包含密码、验证码、Cookie、支付信息、完整收货地址或其他敏感数据。

每份 handoff 至少包含以下内容：

```markdown
# 任务名称

## 本轮目标

## 已完成内容

## 修改过的文件

## 当前状态

## 未完成/已知问题

## 下一步建议

## 是否需要用户操作
```

状态发生变化时，同时更新 `status/current.json`，确保其中的 `task`、`status`、`step`、
`message` 和 `updated_at` 与最新 handoff 一致。`updated_at` 使用带时区的 ISO 8601 时间。

提交前必须运行 `git status`，检查并排除截图、缓存、下载文件、浏览器资料、日志、凭据以及
其他与本轮任务无关的内容。不得为了整理 handoff 而覆盖或删除用户已有的未提交修改。
